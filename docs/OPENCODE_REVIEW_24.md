## P1（建议确认，R2 落码前闭环）

### P1-1 【R2】沉默时大狗正处于 CHARGING/FIRING 的处置未定义（行 606）

行 606 只写了"`tick()` 沉默期间仅跳过状态机推进与 IDLE 索敌分支"，**没有定义 silence() 对当前攻击轮的处理**。若按"跳过推进"字面实现（状态冻结），会出现三个连带问题：

1. **声音残留**：客户端 `BigDogEntitySound` 只在 STATE 变化时 `stop`（第二迭代死亡截断架构）。CHARGING 冻结 → STATE 保持 CHARGING → 蓄力音持续响满 45s，"沉默期声音正常停止"（R2 验证条）**必然失败**。
2. **蓄力护甲续挂**：CHARGING 冻结 → `CHARGING_ARMOR_BONUS`（+8，16 甲）随冻结期挂 45s，超出"蓄力窗口"语义。
3. **语义与用户拍板不符**：用户 B 组拍板是"**硬停**大狗叫一切攻击 45s"——"跳过推进再恢复"是"暂停"而非"停止"；45s 后冻结的 CHARGING 继续走完剩余 tick 再发射，玩家预期的"戳完它就不打了"会落空。

**建议**：`silence(int)` 内显式 `cancelAttack()`（STATE→IDLE、清 `chargingTarget`/`firingDir`/`FIRING_PROGRESS`、移除护甲 modifier、`revengeTarget` 照设但不进入攻击），45s 内状态机与索敌跳过，结束自动恢复 IDLE 门控。`cancelAttack()` 复用现有实现（幂等，安全）。并在 R2 验证补一条："**CHARGING 中被戳 → 立即取消、蓄力音即停、护甲回落 8**"。
