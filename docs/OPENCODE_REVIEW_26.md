## P2（低优先级，R3 落码时顺手处理）

1. **顶层验证 4 与 R3 定稿语义不一致（行 639）**：顶层验证方案仍写"3 鸡同目标播 BGM **出 3 波大狗**"，R3 定稿是"共享池累计 3 次 → 生成 **1 只**大狗"（行 621）。验证方案 4 需同步为"累计 3 次 BGM → 生成 1 只大狗"。
2. **"无口罩玩家超 3 循环"与共享池 3 次的计数关系未定义（行 621）**：是同一计数（3 次时同时触发"生成大狗 + 强制骑红马"）还是独立计数（共享池 3 次 → 大狗；玩家单独累计 3 次 → 红马）？另外生成大狗后计数是否重置再循环（temp.txt"播放完 3 次 BGM 就会生成大狗叫"读起来像循环刷）。建议 R3 落码前定：**同一计数、生成后重置循环**（简化为一个状态机：count 0→1→2→3 触发两件事 → 归零）。
3. **强制骑乘的 1.20.1 马鞍/驯服前置未提（行 621）**：1.20.1 原版马**无鞍不可骑**（`HorseEntity.canBeRiddenBy` + `isHorseSaddled`），服务端直接 `startRiding` 会被否决。建议注明"生成红马时自动装备鞍（`equipSaddle`/`setSaddled`）+ 驯服标记"，否则"强制骑乘"落码时会发现骑不上去。
4. **R3 生成红马依赖 R4 的 `horse_color` 标记（行 621）**：按 R1→R4 顺序落码时，R3 落码时 R4 未落，生成的"红马"会是普通马。建议在 R3 注明依赖处理：R4 的红马标记接口（`HorseColorUtil.setRed(horse)`）先出，或 R3 先落占位普通马、R4 落码时补标记（并在验证中注明）。
5. **"掉落沿用原版鸡"需要显式覆写 `getLootTableId()`（行 618）**：继承 `ChickenEntity` 不会自动沿用原版掉落表（`EntityType` 默认按自身 ID 找 loot table）。需覆写返回 `EntityType.CHICKEN.getLootTableId()`，或自备 `loot_tables/entities/dingdong_chicken.json`。
6. **90s 坚守者计时起点/重置条件未定义（行 622）**："进入计时"从发现无马起还是从开始跟随起？玩家中途骑上马是否重置？建议注明：从开始跟随起算，骑上红/绿马即取消计时，之后每 5 分钟补查。
