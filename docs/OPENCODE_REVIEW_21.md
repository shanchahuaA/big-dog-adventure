## P1（建议确认，落码前闭环）

### P1-1 【R4】"NBT 透传"实际需要第 2 个 Mixin，铁律需用户拍板（行 598、603）

计划写 `NBT horse_color=red/green 透传 write/readCustomDataToNbt`，但 1.20.1 的**原版** `HorseEntity`（复用原版马 = 不新写实体）的 NBT 读写方法**没有公开注入点**——Fabric API 在 1.20.1 无 EntityDataSaver 之类能力。把自定义 NBT 存进原版马，只能再写 1 个 Mixin 拦 `HorseEntity#writeCustomDataToNbt/readCustomDataFromNbt`。即 R4 实际是 **2 个 Mixin**（NBT 透传 + 下马拦截），计划只列了 1 个。

铁律："不引入 Mixin（除非计划明确接受）"。**R4 落码前需用户拍板接受 2 个 Mixin**，或改用备选：

- 方案 A（推荐，若用户同意 Mixin）：2 个 Mixin，NBT 持久化，重启不丢。
- 方案 B（零 Mixin）：服务端内存 `Map<UUID, Color>` 运行时标记，重启后变普通马（红绿状态丢失）。
- 方案 C：换思路绕过——把"红/绿"做成马的**视觉形态**（如给马穿不可拆卸的马铠/命名），不存自定义 NBT。命名（`HorseEntity` 的 `CustomName` 原版字段可写）可持久化且零 Mixin，但会被玩家改名干扰，需权衡。

### P1-2 【R2】两个新配方不在 A 组破例范围内，需用户逐条拍板（行 590）

A 组拍板仅破例"5 棉 + 2 线 → 1 口罩"一条配方（REVIEW_20 第 11 行）。R2 又列了 **"棉 → 线"** 与 **"1 棉 + 1 棍 → 棉签"（火把式）** 两个新配方，均属铁律"不擅自加生存配方"范围。需用户在 R2 细节轮逐条确认；若只拍板棉签配方、否掉"棉 → 线"，口罩配方仍可成立（"2 线"原版自有渠道：蜘蛛丝/羊毛，不依赖棉→线），请计划注明"棉→线为可选便利配方，待拍板"，避免阻塞主配方。

### P1-3 【R1】群系"其余低密度"非用户终字，落码门控要写明（行 572、586）

A 组拍板：恶地 + 沙漠（REVIEW_20 第 12 行）。"恶地高密度、其余低密度"是 C 组差异的**并集建议**，用户尚未终字。计划已标"群系终值等合并确认"，但需再明确一条落码门控：**用户确认前，R1 只按 A 组（恶地 + 沙漠两群系）实现**，"其余低密度"不得先落进去。否则若用户最终否掉并集，R1 又要回改。

### P1-4 【R2】沉默的 `tick() 首行 cancelAttack + return` 范围需明确（行 590）

"硬停一切攻击"如果写成整个 `tick()` 首行 return，会连带跳过：`silencedUntilTick` 自身递减、DataTracker 更新、客户端声音停止检查（`BigDogEntitySound` 依赖 STATE 变化才会 `stop`）、以及 `lookAt`/导航清理。建议明确为"**仅跳过状态机推进与索敌分支**（`tickCharging/tickFiring/enterCooldown/IDLE 索敌`），计数器递减与 DataTracker/声音路径照常跑"，或写明"return 后由其他路径负责停止声音"。否则 45s 沉默期间可能出现声音残留或沉默永不结束的 bug。

### P1-5 【R3】叮咚鸡仇恨逻辑"拷贝"需注明扫描节流与目标共享语义（行 594）

大狗 `findPreferredTarget` 每 tick 扫 64 格 Box（IDLE 且无目标时）。若叮咚鸡逐只拷贝且村庄每村 3 只 + 低概率野外生成，多鸡同场时每 tick 多份 64 格扫描，需注明**扫描节流**（如每 20t 一次或范围收缩）。另"≥3 只面向同一目标 → 播 BGM、3 次共享池"建议在 R3 细节轮明确计数归属（每只鸡各 3 次 vs 群体合计 3 次）与生成大狗的位置/数量/初始仇恨目标（是否继承鸡群目标）。
